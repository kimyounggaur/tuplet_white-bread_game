## 0. 읽는 법

이 문서는 『잇단음표 식빵 공방』 v1.0의 설계와 실행 순서를 담는다. 기획안의 결정 D1~D8은 2026-11-14에 모두 권장안으로 확정되었다. 이 문서는 기획안의 4~7장을 확정 수치로 채우고, 주문 목록, 상태 전이, 저장 구조, 화면 사양, 검사 목록, 참조 구현을 더한다. 기획안과 어긋나는 곳은 이 문서가 우선한다(1.3절).

핵심 수치와 주장에는 근거 수준을 붙였다.

| 표기 | 뜻 |
|---|---|
| **[검증]** | 별첨 2(일부는 별첨 1)를 실행해 동작을 확인한 것 |
| **[계산]** | 스파이크에 들어 있는 엔진을 그대로 써서 계산한 값 |
| **[확정]** | 2026-11-14에 정한 결정 |
| **[설계]** | 이 문서의 제안값. 아직 실행으로 확인하지 않았다 |
| **[결정]** | 진행 전에 정해야 하는 항목. 권장안을 함께 적었다 |
| **[초안]** | 드라이브 초안에서 온 원칙 |

검증은 모두 헤드리스 Chrome 153의 모바일 에뮬레이션(터치, 화면 배율 2)에서 했다. 배치는 일곱 화면(320×568, 360×600, 360×640, 390×664, 390×844, 430×932, 800×600)에서 화면마다 24개 지점을 쟀고, 흐름과 소리는 390×844에서 주문 일곱 개를 끝까지 실행했다. 소리는 오실레이터 생성을 가로채 주파수, 예약 시각, 취소 여부를 기록하는 방식으로 쟀다(부록 C.8).

**실기기에서는 아무것도 재지 않았다.** 손가락으로 박을 치는 감각, 터치와 소리의 지연, 폰 스피커의 음색과 음량, iOS Safari의 오디오 정책은 이 문서의 어떤 수치에도 들어 있지 않다. 헤드리스에서 넣은 탭은 화면 갱신 주기에 맞춰 들어가므로 사람 손의 흔들림도 들어 있지 않다. 부록 A에 폰에서 확인할 여섯 가지를 적었고, 정식 확인은 SL9에서 한다.

**용어.** 기획안의 용어를 그대로 쓰고 아래를 더한다.

| 말 | 뜻 |
|---|---|
| 덩이 | 식빵 한 개. 나누기 전의 원래 음표 하나와 길이가 같다 |
| 조각 | 덩이를 같은 크기로 나눈 것 하나. 음 하나다 |
| 칼집 / 칼질 | 자를 자리를 표시한 점선 / 실제로 자르는 동작 한 번 |
| 보통 칸(틀) | 덩이를 잇단음표 없이 나눈 칸 |
| 선반 / 도마 | 덩이들을 실제 비율로 늘어놓은 영역 / 고른 덩이를 확대해 보는 작업 영역 |
| 재단 / 썰기 | 시간 압박 없이 칼집 수를 정하는 단계 / 박에 맞춰 탭해서 자르는 단계 |
| 이름표 | 조각에 붙는 악보 표기(음표와 잇단 숫자) |
| 숫자 질문 | "이 조각에 잇단 숫자가 필요한가"를 묻는 이름표 단계(2단) |
| 유령 빵 | 틀린 이름표나 틀린 덩이의 전체 시간을 점선 막대로 보여 주는 것 |
| 납품 | 주문의 마지막 단계. 원래 소리와 조각 리듬을 듣고 기록한다 |
| 주문 / 영업일 | 문제 한 개 / 한 판(주문 6~8개) |
| 마감 주문 | 영업일의 마지막 주문. 도움이 꺼져 있다 |
| 발견 장면 | 주문 사이에 끼는 비교 화면. 채점하지 않는다 |
| 레시피 / 칼솜씨 | 주문 하나의 개념 기록(●, ◐) / 썰기 기록(장인, 고른 편, 들쭉날쭉, 기계, –) |
| 판독 줄 | 도마 아래 한두 줄의 안내와 피드백 |
| 탭 패드 | 썰기 단계의 큰 단추 |

## 1. 한 장 요약

### 1.1 결론

만들 수 있다. 기획안이 "설계서 단계의 스파이크에서 잰다"고 미뤄 둔 것을 주문 스파이크로 확인했다 [검증].

1. **한 화면에 들어간다.** 일곱 화면의 모든 단계에서 스크롤 0, 잘림 0이다. 조작부를 94px로 고정해 단계가 바뀌어도 배치가 움직이지 않는다.
2. **주문 흐름이 돈다.** 고르기 → 재단 → 이름표 → 썰기 → 납품을 주문 일곱 개(고르기, 말, 연속, 악보, 소리)로 끝까지 실행했다. 오답 경로(1차 원인 안내, 2차 교정)와 키보드만의 조작도 통과했다.
3. **소리와 판정이 같은 시계로 맞는다.** 듣기의 음이 계산한 시각에 예약되고, 재생을 다시 시작하면 앞선 예약이 시작 전에 취소되며, 소리 시계가 멈추면 썰기를 중단하고 알린다.

남은 일의 무게중심은 조작 코드가 아니라 **내용(주문 43개, 발견 장면 4개, 레시피 카드 15장), 그림, 실기기에서의 박자 감각**이다.

### 1.2 확정된 결정

| # | 결정 | 확정 내용 [확정] |
|---|---|---|
| D1 | 코어 조작 | 재단 + 썰기 2단. 진행은 고르기·재단·이름표의 정답으로만 열고 썰기는 칼솜씨로 따로 기록한다 |
| D2 | 대상과 말투 | 초등 3학년부터 성인 입문자. 수업 시연과 혼자 연습 겸용. 해요체 |
| D3 | 화면 방향 | 세로 우선 반응형(320×568부터) |
| D4 | 그리기 | DOM + SVG |
| D5 | 악보 | 1선 리듬보. 음표를 조각이 시작하는 자리 아래에 둔다 |
| D6 | 보상 | 레시피 카드와 영업일 도장. 재화, 상점, 순위표 없음 |
| D7 | 교사용 기능 | v1.0은 자유 도마만 |
| D8 | 음색 | 조각은 짧은 타악성 음 하나, 원래 소리는 한 옥타브 아래 지속음, 메트로놈과 칼 소리는 잡음 |

새로 생긴 결정 D9~D13은 3.3절에 있다. SL0~SL7은 그 답 없이 진행할 수 있다.

### 1.3 기획안에서 달라진 것

| 항목 | 기획안 | 설계서 | 이유 |
|---|---|---|---|
| 판정 허용폭 | max(조각의 15%, 50ms) / max(30%, 90ms) | 천장을 둔다. 15%는 120ms까지, 30%는 240ms까지 | 온음표 2조각(조각 2초)에서 0.3초 어긋나도 "장인"이 되었다 |
| 재단 조작 | − / + | − / + 와 빵 탭(하나씩 늘고 끝에서 0으로) | 연속 주문에서 덩이마다 정해야 한다 |
| 2단의 이름표 | 자동 표시 | 숫자 질문(필요해요 / 필요 없어요) | 틀을 보고 스스로 판단하는 걸음이 3지선다 앞에 필요하다 |
| 소리 주문 | 리듬을 들려준다 | 원래 소리 → 조각 리듬 | 일반 분할은 리듬만으로 덩이를 가릴 수 없다(2.4절 4번) |
| 선반 | 늘 같은 크기 | 고르기 단계에서만 크게, 그 밖에는 작게 | 한 화면 |
| 틀의 글자 | 이름과 길이 | 칸이 104px보다 좁으면 이름만 | 320px 폭의 여러 칸 틀 |
| 가장 작은 글자 | 11px | 12px | v1.0은 4조각까지라 여유가 있다 |
| 검사 | 24개 | 페이지 안 51개 + 화면 점검 8개 | 이름표, 판정, 주문, 상태 검사가 늘었다 |
| 문제 수 | "주문 6~8개 × 6일" | 주문 43개를 씨앗으로 확정(7.3절) | 엔진으로 전부 계산해 검사했다 |

### 1.4 큰 위험 세 가지

1. **실기기의 탭 감각과 지연을 모른다.** 썰기의 판정은 터치 입력과 소리 출력의 지연에 휘둘린다. 박자 보정(6.6절), 허용폭의 바닥값, "썰기는 진행 관문이 아니다"(R8), 기계 썰기로 막았지만 수치는 폰에서 맞춰야 한다. 두 스파이크를 폰에서 열면 지금 확인할 수 있다(부록 A).
2. **초반이 단조로울 수 있다.** 2단은 4분음표 덩이만 쓰고 주문 7개 가운데 4개가 같은 3조각이다. 발견 장면 둘, 숫자 질문, 안내선 끄기, 마감 주문으로 변화를 주었지만 재미는 재지 않았다. 강사 검수에서 본다(SL9).
3. **그림이 없다.** 스파이크의 평면 도형은 임시다. 그림 방향(D9)이 정해져야 SL8을 시작할 수 있다.

## 2. 스파이크로 확인한 것

### 2.1 두 스파이크

| | 별첨 1 썰기 스파이크 | 별첨 2 주문 스파이크 |
|---|---|---|
| 목적 | 재단, 틀, 썰기의 감 | 제품 배치, 주문 흐름, 오답 처리, 복구 |
| 화면 | 세로로 긴 페이지 | 한 화면 |
| 주문 | 없음(자유 조작) | 7개: 고르기, 말(일반 분할), 말(숫자 질문), 말(이름표 고르기), 연속, 악보, 소리 |
| 조각 수 | 2~7 | 2~4 |
| 자가검사 | 12개 | 26개 |
| 판정 허용폭 | 천장 없음 | 천장 있음(이 문서의 값) |

제품의 자유 도마(7.6절)는 별첨 1의 화면을 별첨 2의 틀 안에 넣은 것이다.

### 2.3 확인하지 못한 것

- 실제 손가락의 박자 정확도와 터치 지연, 무선 이어폰의 출력 지연, 탭 보정값의 분포.
- 폰 스피커에서의 음색과 음량, 메트로놈 잡음이 조각 음을 가리는지.
- iOS Safari와 Android Chrome의 첫 재생 허용, 다른 앱에 다녀온 뒤의 복귀, 무음 스위치.
- 0단의 이름 고르기와 이어 붙이기 주문, 발견 장면, 레시피북, 영업일 지도, 저장, 박자 보정 화면(함수만 검사했다).
- 어린 학습자가 틀과 유령 빵의 뜻을 설명 없이 알아보는지.
- 영업일 하나에 걸리는 실제 시간과 지루함.

### 2.4 스파이크가 드러낸 것

1. **재시작 보호가 다음 주문을 막았다.** 썰기가 끝난 직후의 탭이 다시 시작으로 읽히지 않게 0.6초를 막았더니, 다음 주문의 "썰기 시작"까지 막혔다. 주문이나 단계가 바뀌면 보호를 푼다(검사 ST-04).
2. **소리 시계가 서면 썰기가 끝나지 않는다.** 커서와 판정이 오디오 클록을 따르므로 컨텍스트가 멈추면 화면이 "여기를 탭!"에서 굳는다. 0.8초 넘게 시계가 서 있으면 중단하고 알린다(R13, 검사 AU-05).
3. **고르기 단계에서 도마가 모자란다.** 선반이 커지고 유령 빵까지 뜨면 320×568에서 8px, 360×640에서 2px이 잘렸다. 고르기 단계의 덩이 높이를 42~46px로 줄여 해결했다. 좁음 모드에서는 고르기 줄이 38px이다(R10의 예외).
4. **일반 분할은 리듬만으로 덩이를 가릴 수 없다.** 1박 덩이의 2조각과 2박 덩이의 4조각은 둘 다 8분음표의 연속이다. v1.0의 11조합에서 조각 길이가 겹치는 것이 세 쌍이다(1박, ½박, 1/4박) [계산]. 그래서 소리 주문은 원래 소리(덩이의 길이)를 먼저 들려주고 조각 리듬을 들려준다. 악보 주문은 묶는 줄과 괄호가 덩이를 정한다.
5. **유령 빵이 덩이보다 길면 도마의 배율이 바뀐다.** 한 영역 한 배율(R1)을 지키면 덩이가 줄어들어야 한다. 배율은 "도마 폭 ÷ 올라온 것 가운데 가장 긴 박 수"다.
6. **연속 주문의 "칼집 n"이 점선과 겹쳤다.** 글자에 빵 색 바탕을 깔았다.
7. **HUD가 320px에서 넘친다.** 제목, 진행 점 7개, "소리 켜기", "설정"이 한 줄에 안 들어간다. "소리 켜기"가 보이는 동안 420px 미만에서는 제목을 숨긴다.
8. **한글이 낱말 중간에서 끊긴다.** `word-break: keep-all`을 기본으로 둔다. 연속 주문의 "2 · 3 · 4 · 3"은 줄이 갈리지 않게 묶어야 한다(스파이크는 320px에서 갈린다).
9. **높은 화면에서 도마만 길어진다.** 도마 높이에 상한(340px)을 두고 남는 높이는 행 사이에 나눈다.
10. **눕힌 폰에서는 성립하지 않는다.** 고정 행과 여백이 349px이고 도마의 내용이 최대 196px이라 높이 550px부터 성립한다 [계산].
11. **허용폭에 천장이 필요하다.** 1.3절 첫 줄.
12. **"납품"이 "썰기 시작"과 같은 색이면 썰기를 건너뛰기 쉽다.** 썰기 결과가 나오기 전에는 보조 단추로 그린다.

### 3.4 세계와 말투

- 공방의 간판은 박자표다. 본점은 4/4, 겹박자는 6/8 분점(v1.2)에서 배운다 [설계].

- 문구는 해요체, 한 번에 두 문장 이내. 수치는 엔진이 넣는다(R3).

## 4. 코어 설계

### 4.1 영역

영업 화면은 여섯 줄이다. 위에서부터 HUD, 주문 카드, 선반, 도마, 판독 줄, 조작부. 선반은 덩이를 고르는 곳이면서 실제 비율의 길이 비교표이고, 도마는 고른 덩이를 폭에 맞춰 확대한 작업대다. 조작부는 단계마다 내용만 바뀐다.

### 4.2 주문 방식과 단계

| 주문 방식 | 주문 카드 | 단계 | 쓰는 단 |
|---|---|---|---|
| 고르기 | 문장(박 수, 음표 이름, 이어 붙이기) 또는 소리 | 고르기 → 납품 | 0 |
| 말 주문 | "2박 식빵(2분음표)을 같은 크기 3조각으로 썰어 주세요." | 재단 → (이름표) → 썰기 → 납품 | 1~3 |
| 말 주문(연속) | "1박 식빵 4개를 차례로 2 · 3 · 4 · 3조각으로 썰어 주세요." | 재단(덩이마다) → 썰기 → 납품 | 4 |
| 악보 주문 | 문장 + 악보 쪽지 | 고르기 → 재단 → 썰기 → 납품 | 5 |
| 소리 주문 | 문장 + "주문 듣기" 단추 | 고르기 → 재단 → 썰기 → 납품 | 5 |

이름표 단계는 주문 씨앗의 `label` 값으로 정한다. `auto`(1단: 맞히면 이름을 말해 준다), `yesno`(2단: 숫자 질문), `choose`(3단: 보기 3개), 없음(4단, 5단).

### 4.3 고르기

[검증: 박 수, 악보, 소리 주문. 설계: 이름, 이어 붙이기 주문]

- 선반이 커진다(줄 44px, 좁음 모드 38px). 줄을 누르면 그 덩이가 도마에 올라오고 "확정"으로 답한다. 줄을 누르는 것만으로는 채점하지 않는다.
- 고르지 않고 확정하면 안내만 한다.
- 1차 오답: 원인 문구. 악보·소리 주문에서는 필요한 길이를 유령 빵으로 보여 준다.
- 2차 오답: 정답 덩이를 올려 주고 확정을 기다린다. 그 주문의 레시피는 ◐다.
- 이어 붙이기 주문: 도마에 작은 덩이 여러 개를 이어 놓고(선반과 같은 배율) 길이가 같은 덩이를 고르게 한다 [설계].

### 4.4 재단

[검증]

- 덩이가 칼집 0으로 도마에 올라온다. − / + 또는 빵 탭으로 칼집 수를 바꾼다. 빵 탭은 하나씩 늘고 끝(한 덩이 6, 연속 주문 3)에서 0으로 돌아간다.
- 칼집은 늘 같은 간격으로 놓인다. 플레이어가 정하는 것은 수뿐이다.
- 판독 줄: 연습 주문에서는 "칼집 2번이면 3조각이에요."처럼 조각 수를 말해 준다(`count`). 마감 주문에서는 "칼집 2번."만 말한다.
- 틀: 2단부터 덩이 위에 둔다. 지금의 조각 수에 맞는 보통 칸이 따라 바뀐다(칼집 0이면 한 칸, 1~2면 2칸, 3이면 4칸).
- 연속 주문: 덩이 넷이 나란히 놓인다. 덩이를 탭하면 그 덩이의 칼집이 늘고 테두리가 바뀐다. 덩이 안에 "칼집 n"을 적는다. − / + 는 마지막에 누른 덩이에 듣는다.
- 1차 오답: 조각에 1, 2, 3 번호를 붙이고 칼집을 실선으로 그린 뒤 원인을 말한다. 칼집 수를 바꾸면 표시가 풀린다.
- 2차 오답: 칼집을 고쳐 두고 확정을 기다린다(◐).

### 4.5 이름표

[검증]

**숫자 질문(2단).** 틀과 조각을 함께 보여 주고 "이 조각에 숫자(잇단 표시)가 필요할까요? 틀과 견주어 보세요."를 묻는다. [숫자가 필요해요] [필요 없어요]. 틀리면 근거를 말하고 틀린 단추를 끈다.

**이름표 고르기(3단).** 보기 3개를 악보 그림과 이름으로 보여 준다. 순서는 주문 씨앗으로 섞는다(같은 주문은 늘 같은 순서).

| 정답의 종류 | 오답 1 | 오답 2 |
|---|---|---|
| 잇단 분할 | 숫자를 빼먹은 것: 같은 음표 n개 | 음표가 한 단계 다른 것: 8분음표 쪽으로 한 단계(정답이 8분음표면 4분음표), 숫자 n |
| 일반 분할 | 한 단계 긴 음표 n개 | 한 단계 짧은 음표 n개 |

오답은 모두 전체 시간이 덩이와 다르다 [계산: v1.0의 11조합, 부록 B.3]. 그래서 오답을 고르면 그 음표들의 전체 시간을 유령 빵으로 그릴 수 있다. 덩이보다 길면 "…보다 길어요", 짧으면 "…에 모자라요". 숫자 없는 보기에는 "숫자가 있어야 들어가요.", 음표가 다른 보기에는 "보통 칸의 이름을 보세요."를 붙인다. 틀린 보기는 꺼진다.

이름표의 전체 시간은 이렇게 계산한다. 숫자가 없으면 음표 길이 × 개수. 숫자 n이 있으면 음표 길이 × (n을 넘지 않는 가장 큰 2의 거듭제곱). 겹박자에서는 주문의 `m`을 쓴다(v1.2).

### 4.7 납품

[검증]

- 원래 소리(덩이 길이의 지속음) → 조각 리듬을 차례로 들려준다. 첫 번째에는 덩이 전체가, 두 번째에는 조각이 차례로 밝아진다.
- 조각이 시작하는 자리 아래에 악보를 그리고, 판독 줄에 이름과 비율을 적는다. 예: "8분음표 셋잇단음표 (3:2). 원래 소리, 조각 리듬 순서로 들어요."
- 고르기 주문은 원래 소리만 들려준다.
- 연속 주문은 덩이마다 원래 소리를 한 번씩 들려준 뒤 전체 리듬을 들려준다. 악보는 그리지 않는다.
- [다시 듣기] [다음 주문]. 듣는 도중에도 넘어갈 수 있다. 마지막 주문이면 [마감하기].
- 납품할 때 레시피(●, ◐)와 칼솜씨를 적는다.

### 4.8 한 주문의 흐름

```
(scene)   발견 장면. [알겠어요] → 다음 주문의 첫 단계                채점 없음
pick      선반에서 고르고 [확정]
            맞음 → mark (고르기 주문이면 deliver)
            틀림 → pick에 머문다. 1차 원인 안내, 2차 정답 덩이를 올려 줌
mark      칼집 수를 정하고 [확정]
            맞음 → label (label이 yesno·choose일 때) 또는 slice
            틀림 → mark에 머문다. 1차 오답 표시, 2차 칼집을 고쳐 줌
label     숫자 질문 또는 보기 3개
            맞음 → slice
            틀림 → label에 머문다. 틀린 단추가 꺼지고 근거(유령 빵)를 보여 줌
slice     ready → count → run → result
            result·ready → count   다시 썰기, 기계 썰기
            count·run → ready       소리 정지, 화면 가림(중단)
            ready·result → deliver  납품
deliver   listen ⇄ ready
            [다음 주문] → 다음 주문의 첫 단계, 마지막이면 close
```

허용하는 전이는 이 그림뿐이다(검사 ST-01). 단계 안에서 틀렸을 때는 단계를 옮기지 않고 표시 상태(`fix`, `ghost`, `wrong`)만 바꾼다.

**레시피 기록.** 그 주문의 고르기, 재단, 이름표를 모두 한 번에 맞히면 ●, 한 번이라도 틀리면 ◐.

### 4.9 문구

스파이크가 실제로 띄운 문구다 [검증]. 수치와 음표 이름은 엔진이 넣는다.

| 단계 | 조건 | 문구 |
|---|---|---|
| 고르기 | 고르지 않고 확정 | 선반에서 식빵을 먼저 골라 주세요. |
| 고르기 | 덩이가 다르다(고르기 주문) | 4분음표 식빵은 1박이에요. 2박짜리를 찾아요. |
| 고르기 | 덩이가 다르다(악보 주문) | 악보는 모두 2박이에요. 4분음표 식빵은 1박이라 모자라요. |
| 고르기 | 2차 오답 | 2분음표 식빵이 2박이에요. 확정을 눌러요. |
| 재단 | 조작할 때(연습) | 칼집 2번이면 3조각이에요. |
| 재단 | 칼집을 n번 냈다 | 칼집을 2번 내면 3조각이에요. 2조각이면 칼집은 1번이에요. |
| 재단 | 그 밖의 오답 | 전체 시간은 맞아요. 조각 수가 달라요. 지금은 4조각이에요. |
| 재단 | 연속 주문의 오답 | 2번째 덩이: 칼집을 3번 내면 4조각이에요. 3조각이면 칼집은 2번이에요. |
| 재단 | 2차 오답 | 2조각이면 칼집은 1번이에요. 고쳐 두었어요. 확정을 눌러요. |
| 숫자 질문 | 물음 | 이 조각에 숫자(잇단 표시)가 필요할까요? 틀과 견주어 보세요. |
| 숫자 질문 | "필요 없어요"가 틀림 | 한 조각 1/3박은 보통 칸(½박)과 길이가 달라요. 숫자가 필요해요. |
| 숫자 질문 | "필요해요"가 틀림 | 한 조각이 보통 칸과 길이가 같아요. 숫자가 필요 없어요. |
| 이름표 | 물음 | 조각들의 이름표를 골라요. 보통 칸의 이름을 보세요. |
| 이름표 | 숫자 없는 보기 | 이 음표들은 모두 3박이라 2박 식빵보다 길어요. 숫자가 있어야 들어가요. |
| 이름표 | 음표가 다른 보기 | 이 음표들은 모두 1박이라 2박 식빵에 모자라요. 보통 칸의 이름을 보세요. |
| 썰기 | 들어갈 때 | 4분음표 셋잇단음표 (3:2). 이제 박에 맞춰 썰어요. / 8분음표 2개 · 일반 분할. 이제 박에 맞춰 썰어요. |
| 썰기 | 조각 수가 다르다 | 조각 수가 달라요 (3 · 4 · 3 · 3조각). 칼집 자리에서만 탭해요. |
| 썰기 | 장인 | 장인 칼솜씨예요. 평균 오차 7ms, 가장 큰 오차 +11ms. |
| 썰기 | 늦었다 | 고른 편이에요. 평균 오차 44ms, 가장 큰 오차 +146ms. 늦게 썰면 그 앞 조각이 두꺼워져요. |
| 썰기 | 빨랐다 | … 일찍 썰면 그 앞 조각이 얇아져요. |
| 썰기 | 기계 | 기계가 정확한 박으로 썰었어요. 소리를 듣고 따라 해 보세요. |
| 썰기 | 소리 정지 | 소리가 멈춰서 중단했어요. 소리를 켜고 다시 시작해 주세요. |
| 납품 | 고르기 주문 | 2분음표 식빵은 2박이에요. 그 길이만큼 소리가 나요. |
| 납품 | 한 덩이 주문 | 8분음표 셋잇단음표 (3:2). 원래 소리, 조각 리듬 순서로 들어요. |

제품에서는 평균 오차의 ms 수치를 어린 학습자에게 보일지 정한다. 수치 대신 "아주 조금 늦었어요"로 바꾸는 설정을 둔다 [설계].

## 5. 이론 엔진

스파이크의 엔진을 그대로 써서 계산했다. 전체 코드는 부록 C.1~C.3이다.

### 5.1 자료형

```ts
type Frac  = { n: number; d: number };            // 기약분수. 길이는 전부 분수로 계산한다
type Spec  = { T: Frac; n: number; m: number; unit: Frac; unitDen: number; piece: Frac; isTuplet: boolean };
type Label = { den: number; count: number; tup: number };   // 이름표: 음표 분모, 개수, 잇단 숫자(없으면 0)
type Order = {
  id: string;                                     // "d3-02"
  ask: "pick" | "word" | "score" | "sound";       // 주문 방식
  loaf: 1 | 2 | 4 | 8;                            // 덩이 = 원래 음표의 분모
  ns: number[];                                   // 덩이별 조각 수. 한 덩이면 [3], 연속이면 [2, 3, 4, 3], 고르기는 [1]
  by?: "beats" | "name" | "join" | "sound";       // 고르기 주문의 묻는 방식
  join?: [number, number];                        // by "join": 이어 놓을 덩이의 분모와 개수
  label?: "auto" | "yesno" | "choose";            // 이름표 단계
  mold?: boolean;                                 // 틀을 보여 준다
  count?: boolean;                                // 재단에서 조각 수를 말해 준다
  guide?: boolean;                                // 썰기 안내선의 처음 상태
  bpm?: number;                                   // 빠르기(없으면 60)
  final?: boolean;                                // 마감 주문
};
```

덩이의 박 수, 보통 칸 수, 이름, 비율, 이름표 보기, 썰기의 덩이 수는 `Order`에 적지 않는다(R3).

### 5.2 공식

- 음표 길이(온음표 = 1): `(2^(dots+1) − 1) / (den × 2^dots)`
- 박 길이: 온음표 기준 길이 × 박 단위의 분모(4/4면 4)
- 덩이의 성격: 기약분수의 분자가 1이면 민음표 덩이(반씩 나뉜다), 3이면 점음표 덩이(셋씩 나뉜다)
- 보통 칸 수 m: 민음표 덩이는 n을 넘지 않는 가장 큰 `2^k`. 점음표 덩이는 n을 넘지 않는 가장 큰 `3 × 2^k`, n이 3보다 작으면 3
- 표기 음표 = `T ÷ m`, 조각 길이 = `T ÷ n`, 잇단 여부 = `n ≠ m`, 비율 = `n:m`
- 칼집 자리 = `k × T/n` (k = 1 … n−1), 음이 시작하는 자리 = `k × T/n` (k = 0 … n−1)
- 이름표의 전체 시간: 숫자가 없으면 `음표 길이 × 개수`, 있으면 `음표 길이 × (숫자를 넘지 않는 가장 큰 2^k)`
- 허용폭: `max(바닥, min(조각 길이 × 비율, 천장))`. 장인은 (15%, 50ms, 120ms), 고른 편은 (30%, 90ms, 240ms)
- 초 = 박 × 60 ÷ bpm. 화면 길이 = 박 × 그 영역의 px/박. 빠르기는 길이를 바꾸지 않는다
- 주파수 = `440 × 2^((midi − 69) / 12)`

### 5.4 표기 규칙

- 잇단 괄호와 숫자는 늘 그린다. 판독 줄에는 n:m 전체를 적는다 [초안: 관례상 생략되는 정보도 입문 화면에서는 보여 준다].
- 8분음표보다 짧은 음표는 묶는 줄로 그린다(8분 1줄, 16분 2줄, 32분 3줄). 한 묶음이 한 덩이다.
- 일반 분할은 "8분음표 2개 · 일반 분할"처럼 적고 잇단음표라고 부르지 않는다(검사 CT-03).
- 겹박자의 표기는 관례가 갈린다(D13). 주문에 `m`을 명시할 수 있고 화면에는 늘 n:m 전체를 적는다.
- 1박 덩이의 6조각은 16분음표 여섯잇단(6:4)이다. 셋잇단 둘(3+3)과 길이는 같고 묶음이 다르다. v1.1에서 다룬다.

### 5.5 출제 제약

- v1.0의 조각 수는 2, 3, 4다. 8분음표 덩이는 2, 3만 쓴다. 표기 음표는 16분음표까지다 [계산: 주문 43개].
- 이름표 고르기를 쓰는 조합(1박÷3, 2박÷3, 4박÷3, ½박÷3, 2박÷4, 1박÷2)의 보기에는 32분음표가 나오지 않는다 [계산].
- 썰기가 있는 주문은 한 조각이 150ms 이상이어야 한다. v1.0에서 가장 짧은 조각은 8분음표 덩이 3조각의 200ms(♩=50)다 [계산].
- 모든 주문은 풀 수 있어야 하고, 마감 주문은 영업일의 마지막에 온다(검사 GN-01, GN-04).

### 5.6 잠금 정답표

부록 B에 있다. 전부 엔진이 만든 값이다. 프롬프트 가이드의 Step 0에 그대로 넣는다.

## 6. 소리 설계

### 6.1 원칙

1. 납품할 때마다 원래 소리와 조각 리듬을 들려준다. 둘은 같은 박에서 시작해 같은 길이 뒤에 끝난다.
2. 모든 재생은 오디오 클록에 한 번에 예약하고 묶음으로 취소한다(R5).
3. 음높이가 있는 소리는 둘뿐이다(R6).
4. 소리가 꺼져 있거나 멈추면 화면이 그렇다고 말한다(R13).
5. 주파수는 `440 × 2^((midi − 69) / 12)`만 쓴다.

### 6.2 음색

스파이크의 구현값이다 [검증: 주파수와 예약 시각. 실제 청취는 미확인].

| 소리 | 만드는 법 | 쓰임 |
|---|---|---|
| 조각 음 | 삼각파, MIDI 79(783.99Hz). 8ms에 최고값, 그 뒤 감쇠. 길이 0.14~0.22초 | 조각의 시작, 덩이의 첫 음, 칼질 |
| 원래 소리 | 삼각파, MIDI 67(392.00Hz). 덩이의 시간만큼 유지하고 마지막 0.05초에 줄인다 | 나누기 전의 길이 |
| 메트로놈 | 대역 통과 잡음 35ms(센박 2600Hz, 여린박 1700Hz, Q 6) | 박 |
| 칼 소리 | 잡음 40ms(3200Hz) + 조각 음 | 탭, 기계 썰기 |
| 마스터 | 게인 0.8 → 출력 | |

음량과 필터 값은 SL3에서 실제 폰 두 대 이상으로 들어 보고 고친다. 메트로놈이 조각 음을 가리면 메트로놈의 음량을 먼저 내린다.

### 6.3 재생 네 가지

| 재생 | 시작 | 준비 박 | 소리 | 화면 |
|---|---|---|---|---|
| 주문 듣기 | 소리 주문 카드의 단추 | 2 | 원래 소리 → 조각 리듬 | 없음. 길이를 눈으로 알려 주지 않는다 |
| 납품 듣기 | 납품에 들어갈 때, [다시 듣기] | 2 | 원래 소리 → 조각 리듬(고르기 주문은 원래 소리만) | 커서, 덩이와 조각의 강조 |
| 썰기 | 탭 패드 | 4 또는 2 | 메트로놈, 덩이의 첫 음, 탭할 때 칼 소리 | 커서, 칼질 |
| 기계 썰기 | [기계 썰기] | 4 또는 2 | 메트로놈, 덩이의 첫 음, 칼집 시각마다 칼 소리 | 커서, 칼질 |

**예약 규칙** [검증].

```
t0   = 지금 + 0.12초                         준비 박의 첫 박
tb0  = t0 + 준비 박 × 한 박의 초              본 구간의 시작
듣기   P = max(1, 올림(전체 박))               한 번의 재생이 차지하는 박 수
       메트로놈   tb0 + k박 (k = 0 … P × 재생 횟수). 재생이 시작하는 박은 센박
       원래 소리  덩이 q마다 tb0 + q × 덩이 박, 길이 = 덩이 박
       조각 리듬  tb0 + (P + q × 덩이 박 + i × 덩이 박 ÷ n_q)박
썰기   메트로놈   tb0 + k박 (k = 0 … 올림(전체 박))
       첫 음      덩이 q마다 tb0 + q × 덩이 박
       기계 칼    tb0 + (q × 덩이 박 + k × 덩이 박 ÷ n_q)박 (k = 1 … n_q − 1)
끝     tb0 + 구간 박 + 0.3초
```

- 덩이가 1박보다 짧으면(8분음표) 원래 소리 뒤에 다음 박까지 쉬고 조각 리듬을 시작한다.
- 새 재생을 시작하면 앞선 재생의 모든 노드에 `stop()`을 부른다. 아직 시작하지 않은 음은 소리를 내지 않고 끝난다.
- 썰기와 기계 썰기를 새로 시작하면 도마의 칼질 표시를 지운다. 듣기는 지우지 않는다.

### 6.4 시계

- 지금 들리는 시각 = `ctx.currentTime − (ctx.outputLatency || ctx.baseLatency || 0)`.
- 커서의 자리와 탭의 박 위치를 모두 이 시각으로 계산한다(R7). 탭에는 탭 보정값을 뺀다.
- 소리를 쓸 수 없으면(컨텍스트를 만들지 못했거나, 시작 1.2초 뒤에도 시계가 움직이지 않으면) 화면 시계(`performance.now()`)로 이어 간다. 이때 예약한 소리는 모두 취소한다.

### 6.5 언락과 복구

- 전역에서 `click`, `touchstart`, `keydown`에 언락을 건다. 언락은 컨텍스트가 없으면 만들고 `running`이 아니면 `resume()`을 부른다. 재생을 시작하는 단추의 `click` 처리기에서도 부른다. 아티팩트 환경에서는 클릭 처리기 안에서 시작한 재생만 허용된다.
- **소리 상태를 숨기지 않는다.** 컨텍스트가 `running`이 아니면 HUD에 "소리 켜기"가 보인다. `statechange`를 듣고 갱신한다 [검증].
- **정지 감시.** 재생 도중 지금 들리는 시각이 0.8초 넘게 그대로면 재생을 중단하고 준비 상태로 돌아간다. `statechange`로 `running`이 아니게 되었을 때와 화면이 가려졌을 때(`visibilitychange`)도 같다 [검증: 컨텍스트 정지].
- 무음 스위치는 감지할 수 없다. 튜토리얼 첫 장에서 음 하나를 들려주고 "소리가 들리나요?"를 묻는다 [설계].
- 소리 없이도 고르기(박 수, 이름, 이어 붙이기), 재단, 이름표는 전부 풀 수 있다. 썰기는 커서와 안내선으로 할 수 있다. 소리로 묻는 주문(0단의 마감, 5단의 넷)은 소리가 필요하다고 주문 카드에 적는다 [설계].

### 6.6 박자 보정

[설계. 계산 함수는 검증]

1. 설정의 "박자 맞추기"를 누르면 메트로놈이 ♩=60으로 8번 울린다.
2. 플레이어가 탭 패드로 따라 친다.
3. 탭마다 가장 가까운 박과의 차이(ms)를 모아 가운데 값을 낸다. 0.25초 넘게 벗어난 탭은 버리고, 남은 탭이 4개 미만이면 다시 한다.
4. 가운데 값을 탭 보정값으로 저장한다. 범위는 −100~+200ms.
5. 설정에서 ±10ms씩 손으로 바꿀 수도 있다.

첫 썰기 주문 앞에서 한 번 권하고(건너뛸 수 있다), 썰기 결과가 세 번 이어서 같은 쪽으로 60ms 넘게 치우치면 "박자 맞추기를 해 볼까요?"를 한 번 띄운다.

- 주문은 정해진 순서로 나온다. 다시 해도 순서가 같다.
- 발견 장면은 주문 사이에 끼고 채점하지 않는다.
- ◐로 끝난 주문은 마감 주문 앞에 한 번 더 나온다. 다시 나온 주문의 결과는 레시피 카드에는 적지만 그날의 통과 계산에는 넣지 않는다.
- **통과**: ●가 주문 수의 80% 이상(올림). 썰기 결과는 넣지 않는다(R8).
- 통과하면 다음 영업일이 열린다. 통과한 영업일은 몇 번이든 다시 할 수 있다.
- 걸리는 시간은 영업일마다 2~5분으로 잡는다. 고르기 주문 하나에 약 15초, 그 밖의 주문에 25~35초(재단 6초, 이름표 6초, 썰기 7~9초, 납품 듣기 4~10초)로 어림한 값이고 재지 않았다. 납품 듣기는 건너뛸 수 있다.

## 9. 기술 설계

### 9.1 구조

한 파일 `index.html`이다. 안에서 구획을 나누고 구획 머리에 주석을 단다. 스파이크가 이 순서다.

```
<style>     토큰 → 틀(6행) → HUD → 주문 카드 → 선반 → 도마 → 판독 줄 → 조작부 → 겹쳐 뜨는 화면
<body>      #app: hud, order, shelf, board, readout, controls(단계별 묶음), sheet, close …
<script>
  1 THEORY   분수, 음표 길이, 분할, 이름                    순수 함수
  2 LABEL    이름표, 보기, 전체 시간                        순수 함수
  3 JUDGE    판정, 허용폭, 박자 보정, 씨앗 난수              순수 함수
  4 ORDERS   주문 씨앗, 영업일, 발견 장면, 주문 문장
  5 STATE    상태와 setState, 전이 함수
  6 VIEW     악보 그리기, 도마 모델과 그리기, 선반, render
  7 AUDIO    컨텍스트, 음색, 예약과 취소
  8 RUN      재생 네 가지, 프레임, 탭, 끝내기, 중단
  9 STORAGE  저장과 불러오기, 폴백
  10 SCREENS 타이틀, 지도, 마감, 레시피북, 자유 도마, 설정
  11 TESTS   검사 러너
  12 BOOT    입력 연결, 측정, 시작
```

의존 방향은 1~3 ← 4~5 ← 6~8 ← 10이다. 1~3은 `window`와 `document`를 만지지 않는다.

### 9.2 상태 기계

```ts
type Screen = "title" | "map" | "shift" | "close" | "book" | "free" | "settings" | "calib";
type Phase  = "scene" | "pick" | "mark" | "label" | "slice" | "deliver";
type Sub    = "ready" | "count" | "run" | "result" | "listen";

type State = {
  screen: Screen; day: string; idx: number; phase: Phase; sub: Sub;
  sel: number | null;          // 도마에 올린 덩이(음표 분모)
  cuts: number[];              // 덩이별 칼집 수
  focus: number;               // 마지막에 만진 덩이
  tries: number;               // 이 단계에서 틀린 횟수
  assisted: boolean;           // 이 주문에서 한 번이라도 틀렸는가
  fix: boolean;                // 재단의 오답 표시
  wrong: (number | "y" | "n")[];   // 꺼 둔 보기
  ghost: null | { beats: number; text: string };
  label: string;               // 준비 박 숫자, "원래 소리", "조각 리듬"
  knife: string;               // 이 주문의 가장 좋은 칼솜씨
  hearing: boolean;            // 주문 듣기 중
  msg: { tone: "" | "good" | "warn" | "bad"; text: string };
  results: { recipe: "full" | "half"; knife: string }[];
  // 설정: guide, slow, offset, …
};
```

- 상태는 `setState(patch)` 한 곳에서만 바뀐다. 전이 함수(`pickLoaf`, `confirmPick`, `bump`, `confirmMark`, `answerYesNo`, `chooseLabel`, `toSlice`, `toDeliver`, `nextOrder`, `abortRun`)가 다음 상태를 계산해 `setState`를 부른다 [검증].
- 허용하는 전이는 4.8절의 그림이다.
- 재생(`run`)은 상태 밖의 객체다. 예약 시각, 탭 목록, 종류를 가진다. 프레임 함수는 상태를 직접 바꾸지 않고, 준비 박 숫자나 단계가 바뀔 때만 `setState`를 부른다.
- 타이머(`setTimeout`)로 상태를 바꾸지 않는다. 시간에 따른 변화는 프레임 함수가 오디오 클록을 읽어 만든다. 예외는 화면 크기 변화의 디바운스뿐이다.

### 9.3 뷰

- 틀은 HTML에 한 번 적는다. 조작부의 단계별 묶음도 전부 미리 두고 `hidden`으로 바꾼다(R12).
- 도마는 "무엇을 그릴지"를 상태에서 뽑은 모델을 열쇠로 삼고, 열쇠가 바뀔 때만 다시 만든다 [검증]. 썰기와 듣기 동안에는 모델이 변하지 않으므로 다시 만들지 않는다. 칼질과 색 표시는 그 위에 덧붙인다.
- 도마를 다시 만들 때 포커스가 덩이에 있었으면 같은 덩이에 돌려준다 [검증]. 제품에서는 칼집 수가 바뀔 때 덩이를 통째로 갈지 않고 칼집만 갈아 끼운다 [설계].
- 주문 카드와 이름표 보기는 주문이 바뀔 때만 다시 그린다.
- 덩이와 조각의 자리는 %로 준다(`left = i/n × 100%`). px로 누적하지 않는다.
- 화면 크기가 바뀌면 재생 중이 아닐 때만 도마를 다시 그린다 [검증].

### 9.4 저장

```ts
type SaveV1 = {
  version: 1;
  settings: { volume: number; muted: boolean; guide: boolean; slow: boolean; tapOffsetMs: number;
              calibrated: boolean; showMs: boolean; motion: "system" | "reduced" | "full"; tutorialSeen: boolean };
  days: Record<string, { passed: boolean; stamp: 0 | 1 | 2; runs: number; best: number }>;   // 키 "d0"… stamp 1 도장, 2 장인 도장. best: ● 수의 최고
  recipes: Record<string, { got: boolean; knife: 0 | 1 | 2 | 3 }>;   // 키 "4/3" = 4분음표 덩이 3조각. knife 1 들쭉날쭉, 2 고른 편, 3 장인
  loaves: number[];                                                  // 얻은 덩이 카드(음표 분모)
  stats: { orders: number; clean: number; slices: number; master: number };
  active: null | { day: string; index: number; results: { recipe: 1 | 2; knife: 0 | 1 | 2 | 3 }[] };
};
```

- 키는 `sbg_save_v1`이다. `version: 1`을 지킨다. 필드를 더할 때는 없는 필드를 기본값으로 채우고 버전을 올리지 않는다.
- 손상되었거나 더 높은 버전의 저장을 만나면 기본값으로 시작하되 원본 문자열을 `sbg_save_v1_backup`에 남긴다.
- `localStorage`를 쓸 수 없으면 메모리에만 둔다. 이때 설정 화면에 "이 기기에서는 기록이 저장되지 않아요"를 보여 준다.
- 납품할 때마다 저장한다. 썰기 도중에는 저장하지 않는다.

### 9.5 검사 러너

- `index.html#test`로 열면 영업 화면 대신 검사 결과표를 그린다. 묶음(TH, LB, JD, GN, AU, ST, SV, CT)마다 통과 수와 실패한 검사의 이름을 보여 준다.
- 평소에는 불러올 때 한 번 돌리고 설정 화면에 "자가검사 51/51"만 적는다 [검증: 스파이크는 26/26]. `window.__tests`로 결과를 내어 준다.
- 소리 검사(AU)는 오실레이터 생성을 가로채 기록하는 방식으로 한다(부록 C.8). 실제 소리를 내지 않는다.
- 주소 끝의 `#이름`만 쓴다. 아티팩트 환경에서는 물음표 뒤의 값이 전달되지 않는다.

### 11.2 소리를 검사하는 법

소리는 들어 보지 않고도 검사할 수 있다. 페이지가 뜨기 전에 `createOscillator`를 감싸 주파수, 예약 시각, 취소 여부를 기록한다(부록 C.8). 이 문서의 소리 항목을 모두 이 방식으로 확인했다. 이 방식으로 알 수 없는 것은 실제 음량과 음색, 기기의 재생 허용, 출력 지연이다.

const tol = (pieceMs, ratio, floor, cap) => Math.max(floor, Math.min(pieceMs * ratio, cap));     // 허용폭: 조각 길이에 비례하되 바닥과 천장을 둔다
function judge(taps, Tb, ns, beatMs) {
  const R = ns.length, total = Tb * R, cuts = [];
  let edgeTaps = 0;
  for (const b of taps) {
    const e = Math.round(b / Tb), a = ns[Math.min(R - 1, Math.max(0, e - 1))], c = ns[Math.min(R - 1, Math.max(0, e))];
    if (Math.abs(b - e * Tb) <= (Tb / Math.max(a, c)) * 0.25) { edgeTaps++; continue; }      // 덩이 경계(박) 위의 탭은 칼질로 세지 않는다
    if (b > 0 && b < total) cuts.push(b);
  }
  cuts.sort((x, y) => x - y);
  const loaves = [], devs = [];
  for (let q = 0; q < R; q++) {
    const n = ns[q], piece = Tb / n, pm = piece * beatMs;
    const mine = cuts.filter((b) => b > q * Tb && b < (q + 1) * Tb).map((b) => b - q * Tb);
    const edges = [0].concat(mine, [Tb]), widths = edges.slice(1).map((x, i) => x - edges[i]);
    const ok = mine.length + 1 === n;
    if (ok) mine.forEach((b, i) => { const ms = (b - (i + 1) * piece) * beatMs; devs.push({ r: q, k: i + 1, ms, s1: Math.abs(ms) / tol(pm, 0.15, 50, 120), s2: Math.abs(ms) / tol(pm, 0.3, 90, 240) }); });
    loaves.push({ n, pieces: mine.length + 1, widths, ok });
  }
  const countOk = loaves.every((l) => l.ok);
  const mean = devs.length ? devs.reduce((s, d) => s + Math.abs(d.ms), 0) / devs.length : null;
  const worst = devs.length ? devs.reduce((a, d) => (Math.abs(d.ms) > Math.abs(a.ms) ? d : a)) : null;
  const grade = !countOk ? "count" : devs.every((d) => d.s1 <= 1) ? "master" : devs.every((d) => d.s2 <= 1) ? "good" : "rough";
  return { loaves, countOk, mean, worst, grade, edgeTaps };
}
function calibOffset(taps, clicks) {                                                // 박자 보정: 탭과 가장 가까운 박의 차(ms)의 가운데 값
  const d = [];
  for (const t of taps) {
    let best = null;
    for (const c of clicks) if (best === null || Math.abs(t - c) < Math.abs(best)) best = t - c;
    if (best !== null && Math.abs(best) < 0.25) d.push(best * 1000);
  }
  if (d.length < 4) return null;
  d.sort((a, b) => a - b);
  const m = d.length >> 1;
  return Math.round(d.length % 2 ? d[m] : (d[m - 1] + d[m]) / 2);
}
function rng(seed) { let a = seed >>> 0; return () => { a = (a + 0x6d2b79f5) >>> 0; let t = Math.imul(a ^ (a >>> 15), 1 | a); t = (t + Math.imul(t ^ (t >>> 7), 61 | t)) ^ t; return ((t ^ (t >>> 14)) >>> 0) / 4294967296; }; }
function shuffled(arr, seed) { const r = rng(seed), a = arr.slice(); for (let i = a.length - 1; i > 0; i--) { const j = Math.floor(r() * (i + 1)); [a[i], a[j]] = [a[j], a[i]]; } return a; }

`notesSvg`는 음표 머리의 x 자리들을 받아 묶음 하나를 그린다. 도마의 악보는 조각이 시작하는 자리(`i/n × 폭 + 12`)를, 주문 카드와 이름표 보기는 고른 간격(`evenXs`)을 넘긴다.

### C.6 소리와 재생 시작

### C.7 프레임, 탭, 끝내기, 중단, 입력

`frame`의 첫 부분이 화면 시계로의 전환과 정지 감시다. `swallow`는 썰기 도중에 누른 손가락을 뗄 때 생기는 `click`을 버린다.

### C.8 오디오 스파이(화면 점검용)

페이지 스크립트보다 먼저 실행한다(Playwright의 `addInitScript`).

```js
// page.addInitScript(() => { … }) 안에 넣는다
const log = []; window.__audio = log;
const AC = window.AudioContext; if (!AC) return;
const mk = AC.prototype.createOscillator;
AC.prototype.createOscillator = function () {
  const c = this, o = mk.call(this), e = { freq: null, startAt: null, stopAt: null, calledAt: null, cancels: [] };
  const set = o.frequency.setValueAtTime.bind(o.frequency);
  o.frequency.setValueAtTime = (v, w) => { e.freq = Math.round(v * 100) / 100; return set(v, w); };
  const start = o.start.bind(o); o.start = (w) => { e.startAt = w; e.calledAt = c.currentTime; log.push(e); return start(w); };
  const stop = o.stop.bind(o); o.stop = (w) => { if (w === undefined) e.cancels.push(c.currentTime); else e.stopAt = w; return stop(w); };
  return o;
};
```

- 납품 뒤 `window.__audio`의 주파수와 `startAt`의 차이가 AU-02의 값과 같은지 본다.
- `cancels`가 비어 있지 않고 그 시각이 `startAt`보다 이르면 시작 전에 취소된 음이다(AU-03).
- 주파수를 `setValueAtTime`으로 넣어야 기록된다. 제품 코드도 그렇게 쓴다.
