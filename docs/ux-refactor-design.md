## 1. 진단과 범위
배포판에서 ‘영업 시작 → 영업일 → 0단 첫 출근 → 소리 확인 → 1박짜리 빵 고르기’를 확인했다. 소리 확인 화면에서 ‘안 들려요’를 누른 뒤에야 ‘그냥 시작’이 나타났다. 첫 주문에서는 선반을 누르고 도마를 확인한 뒤 ‘확정’을 누른다. [주문 데이터](https://github.com/kimyounggaur/tuplet_white-bread_game/blob/21eb314/src/orders.js#L3-L17)상 0단 7건은 고르기, 1단 7건은 2·4등분, 2단 발견 장면 S2에서 3등분을 처음 보여 주며 첫 정규 3등분 주문은 d2-02다.

이는 학습 난이도의 문제가 아니라 **핵심 조작을 처음 만나는 순서**의 문제라는 가설이다. 기존 개발 기록의 자동 검사 51/51 및 7개 크기 × 51화면 통과를 사용자 직관성의 증거로 해석하지 않는다. 실제 기기 청음·터치와 학습자 관찰은 [검증 기록](https://github.com/kimyounggaur/tuplet_white-bread_game/blob/21eb314/docs/device-check.md)에서 미실시다.

| 우선순위 | 이번에 바꿀 것 | 이번에 건드리지 않을 것 |
|---|---|---|
| P0 | 새 방문자용 진도 밖 맛보기, 재방문 분기, 무음 비교 | 정규 43개 주문·발견 장면 4개, 해금과 정답표 |
| P0 | 0단 첫 주문과 1단 첫 재단의 버튼 문구·선택 강조·교정 | 기존 학습 페이스, 일반 분할/잇단 판정, 자동 교정 규칙 |
| P1 | 실제 휴대폰에서 발견된 잘림·탐색 문제만 보정 | 대규모 그래픽 교체, 리더보드, 계정, 외부 분석 도구 |
| 나중 | 검증 결과에 따라 다른 주문·게임에 패턴 재사용 | 운영 배포는 구현 및 검증과 별도 결정 |

**불변 조건:** n개 조각에는 내부 칼집이 n−1개다. 시작선은 칼집이 아니다. 빵의 전체 길이가 박 길이에 대응한다. 정규 탭 연주의 실력이나 소리 설정이 진도를 막아서는 안 된다. [기존 설계 규칙](https://github.com/kimyounggaur/tuplet_white-bread_game/blob/21eb314/docs/constitution.md#L38-L51)

## 2. 새 이용자 경로와 화면 문구

| 구간 | 학생에게 보이는 것 | 터치·키보드 동작 | 합격 기준 |
|---|---|---|---|
| 진입, 목표 0~5초 | ‘연습: 같은 한 박, 다른 조각’, ‘이 빵을 똑같이 세 조각으로 나눠요’, 0칼집·1조각 | 도마의 빵 전체가 큰 버튼. 별도 메뉴·음량 점검 없이 바로 누름. ‘건너뛰기’는 보조 동작 | 첫 화면에서 목표와 터치 대상이 보임 |
| 자르기, 목표 5~15초 | 첫 탭 ‘칼집 1개, 2조각’, 두 번째 탭 ‘칼집 2개, 3조각’ | 빵 어디를 눌러도 한 칼집 추가. 1/2 또는 1/3·2/3에 자동 배치. ‘한 번 되돌리기’로 직전 상태로 복귀 | 위치·속도·오디오 권한과 무관. 3회째 터치가 다음 동작으로 오발하지 않음 |
| 비교, 목표 15~30초 | 두 줄 도마, 정렬된 시작·끝선, [두 조각 듣기] [세 조각 듣기] [다음 주문], ‘조각 수가 달라도 둘 다 한 박이에요’ | 첫 줄 또는 둘째 줄을 재생. 새 재생은 앞 재생을 중단. 음이 안 나와도 시각 비교와 다음 주문 가능 | 두 줄의 시작·끝 좌표와 재생 구간이 같음. ‘8분음표 셋잇단음표’와 숫자 3 악보는 비교 화면에서 처음 노출 |
| 정규 진입 | 기존 d0-01, ‘1박짜리 식빵을 골라 주세요’ | [다음 주문]으로 정규 주문 시작. 찾아보기는 기존 영업일 메뉴 | 자동 납품·자동 해금 없이 기존 선택부터 시작 |

**모바일 배치:** 상단에 연습 이름과 한 줄 주문. 중앙에 큰 빵과 진행 숫자. 하단에는 현재 핵심 동작 하나를 가장 또렷하게 두고, 되돌리기·소리·건너뛰기는 보조로 배치한다. 비교 2줄을 위아래로 배치해 두 빵이 동일한 폭을 차지하게 한다. 320px에서 버튼을 가로로 욱여넣지 말고 세로로 배치하며, 낮은 화면과 큰 기본 글꼴에서는 필요한 경우 세로 스크롤을 허용한다. 스크롤보다 먼저 작은 글씨나 좁은 버튼으로 해결하지 않는다.

**입력·접근성:** 새 핵심 버튼 최소 44×44 CSS px를 목표로 한다. 실제 HTML button으로 Enter/Space를 지원한다. 같은 노드를 유지해 칼집 변경에 포커스가 사라지지 않게 한다. 비교로 바뀌면 비교 제목 또는 첫 비교 버튼으로 포커스를 옮기고, 스크린리더 상태 안내에는 ‘현재 2조각’처럼 행동 결과만 전달한다. 매 프레임/매 박에 읽기 알림을 내지 않는다. 색을 보지 않아도 조각 수와 시작·끝을 구분할 수 있어야 한다. 동작 줄이기에서는 재생선 이동 대신 조각과 종료선을 단계적으로 표시하고 정적 비교를 항상 제공한다.

## 3. 상태·저장·오디오 설계

### 3.1 맛보기는 정규 주문 상태와 분리
권장 개념 구조: 별도 `screen: "intro"`, 중첩 `intro = { stage, cuts }`. stage는 `cut` / `compare`. 재생 상태와 취소 토큰은 이 화면에만 연결한다. `d0-00` 생성, S2 강제 이동, 정규 주문 `phase`·`sub`에 맛보기 상태 추가는 금지한다. 맛보기 화면을 `shift` 또는 `free`로 속이지 않는다.

| 이벤트 | 상태/처리 |
|---|---|
| 첫 진입 | #test, #주문, #발견 장면 직행 분기를 기존대로 먼저 처리. 유효한 기존 active가 있으면 기존 ‘이어서 영업’ 우선. 과거 완료·해금 기록이 있는 방문자에게 맛보기를 강제하지 않는다. 완전 신규만 맛보기로 진입 |
| 빵 탭 | 컷 0→1→2만 허용. 2이면 비교 화면 표시. 이벤트 중복·빠른 탭은 2에서 멈춤 |
| 되돌리기 | 컷 2→1 또는 1→0. 재생 중이라면 우선 취소 후 재단 화면 복귀. 컷 0이면 비활성 |
| 비교 재생 | 현재 재생을 취소하고 선택한 줄만 재생. 선택한 버튼과 무음 상태를 보여 줌 |
| 다음 주문 / 건너뛰기 | 재생·애니메이션 취소, 재진입 방지, 맛보기 완료/건너뛰기만 기억. 기존 첫날 진입 함수로 d0-01 열기 |
| 새로고침 / 뒤로 이동 | 완료 전에는 맛보기 초깃값으로 돌아가도 무방. 정상 주문 진행 이후에는 기존 active 복구 방식 유지. 맛보기 재체험은 기존 진도를 바꾸지 않는 별도 경로로 추후 고려 |

저장은 `settings.introSeen` 같은 독립 기본값 하나만 추가하고 v1 구조는 유지한다. 기본값 채움은 기존 읽기·복구 루틴을 따른다. 맛보기 탭·재생·되돌리기에서는 `active`, 점수, 영업일, 미션 해금, 레시피·빵을 쓰지 않는다. 첫 정규 주문을 여는 기존 함수가 active를 만드는 것은 정상이다. 레거시 `advanceTutorial(1)`의 소리 확인 통과 의미는 무음 포함 **정규 진입 시점에서만** 정합되게 연결한다. 이후 코치 단계 2~4는 별개로 보존한다. 로컬 저장이 막혀도 현재 세션에서 최소 맛보기와 정규 주문 진입은 가능해야 한다.

### 3.2 두 리듬은 길이가 같고 음의 시작만 다르다
기존 엔진의 분수와 악보 이름을 재사용한다. 비교판은 하나의 4분음표 길이(1박)만 사용하며, 표시용 재생 구간은 공통 박 길이 T로 계산한다.

| 비교 | 시간표(박 기준) | 배치할 칼집 | 표시 |
|---|---|---|---|
| 2등분 | 음 시작 0, 1/2; 공통 끝 1 | 1/2 | 일반 8분음표 2개 |
| 3등분 | 음 시작 0, 1/3, 2/3; 공통 끝 1 | 1/3, 2/3 | 숫자 3이 붙은 8분음표 셋잇단음표 |

예를 들어 60 BPM이면 T=1초다. 음 길이는 기존 음색의 잔향과 구분하고, **시각상 비교의 끝은 두 경우 모두 1초**다. 두 리듬은 같은 템포·음색·볼륨으로 차례로 들려준다. 준비박·반복을 포함하는 기존 연주·발견 장면 계획을 맛보기에 통째로 호출하지 않는다. 새 비교의 짧은 계획은 기존 엔진의 비율과 기존 오디오 시계·스케줄러·취소 개념을 활용하되, 기존 `planRun`, 판정 허용폭, 보정을 수정하지 않는다. 사용자 탭에서만 오디오 컨텍스트 활성화를 시도하고 실패하면 시각 타임라인으로 진행한다. 숨김·탭 이동·다음 주문·다시 재생·되돌리기 시 이전 재생을 정리한다.

## 5. 구현 순서와 단계별 통과 기준

### UX0 — 기존 동작 고정
- 기준 커밋과 현재 실행본을 기록한다. `node tools/build.mjs`, `node tools/check.mjs`, `node tools/progress.mjs`를 프로젝트 도구 지침대로 실행한다. Playwright/Chromium을 쓸 수 없으면 원인과 미실행 사항을 남긴다.
- 기존 첫 진입, 첫 납품 직후 새로고침과 d0-02 재개, 여섯 영업일 완주 경로를 캡처한다. 신규/중단/완료 저장 상태를 테스트용으로 따로 보존한다.
- **통과:** 기존 주문 수 43, 발견 4, 자가검사 51/51의 기준을 확인한다. 새 검사는 이 분모와 분리한다.

### UX1 — 무음 맛보기 상태와 레이아웃
- 새 진입 분기와 도마를 연결하고 0·1·2칼집, 되돌리기, 비교 화면, 건너뛰기, 정규 진입을 무음부터 완성한다.
- 모바일 320×568 및 360×640, 데스크톱 800×600에서 주문·도마·버튼이 겹치거나 잘리지 않는지 검증한다.
- **통과:** 신규가 정규 메뉴 없이 2회 터치로 비교에 들어가며, 중단 및 재방문 데이터가 보존된다. 시각만으로 동일 시작·끝을 비교할 수 있다.

### UX2 — 1박 비교 소리와 상태 처리
- 2등분·3등분 시간표의 단위 검사, 오디오와 시각 재생선, 버튼 재입력 시 취소, 무음 대체를 넣는다.
- **통과:** 음 시작 [0, 1/2]와 [0, 1/3, 2/3], 공통 종료 1박. 빠른 전환·숨김·나가기 뒤 이전 소리나 타이머가 남지 않는다. 자동 오디오 예약 통과를 실제 청음이라고 쓰지 않는다.

### UX3 — 정규 첫 두 접점의 안내 정리
- d0-01 ‘이 빵 고르기’, d1-01 ‘두 조각으로 썰기’처럼 주문별 행동을 버튼에 명시한다. 잘못 골랐거나 칼집이 적으면 목표와 현재 상태를 한 문장으로 명확히 설명한다.
- 기계 썰기·직접 탭·건너뛰기는 유지하며, 납품 직후 저장과 마지막 ‘마감하기’ 동작을 보존한다. 결과 듣기 때문에 다음 주문을 막지 않는다.
- **통과:** 새 문구에서 정답을 먼저 노출하지 않고, 오답 후 같은 도마에서 다시 시도할 수 있다. 점수·재단 결과·잠금 규칙은 기준판과 같다.

### UX4 — 사용자 검증 및 릴리스 판단
- 아래 시험표를 실행한다. 실제 기기(iPhone Safari·Android Chrome)에서 첫 동작 소리, 무음, 앱 전환, 포커스, 엄지 터치, 되돌리기를 확인한다. 기종·OS·브라우저·폭을 기록한다.
- 초견 5명에게 설명하지 않고 첫 활동만 시킨다. 소요 시간은 화면 노출부터 비교 화면에 들어가기까지로 측정한다. 완료 후 “둘 중에 어느 빵이 먼저 끝나나요?” 그리고 “칼집은 몇 개, 소리는 몇 번인가요?”라고 묻는다. 첫 응답과 설명을 적고 필요하면 두 박짜리로 전이 여부를 본다.
- **통과 목표:** 5명 중 4명 이상이 도움 없이 30초 내 세 조각을 만들고 두 경우가 같은 한 박임을 설명. 칼집 2개/소리 3회 오해는 별도 기록. 이는 출시 전 소규모 점검 목표이지 통계적 보증이 아니다. 기준 미달이면 첫 막힘을 고쳐 재검증하고 배포는 보류한다.

## 7. 구현 시작 시 전달할 지시
